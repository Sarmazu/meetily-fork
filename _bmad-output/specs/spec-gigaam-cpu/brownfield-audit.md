## Что переиспользовать

Пути в таблице относительно корня проекта; области `audio/…` и `gigaam_engine/…` — внутри `frontend/src-tauri/src/`.

| Существующая реализация | Что уже даёт | Минимальное дополнение GigaAM |
| --- | --- | --- |
| `audio/transcription/provider.rs`, `engine.rs` | `TranscriptionProvider`, `TranscriptResult`, `TranscriptionError`, `Provider(Arc<dyn TranscriptionProvider>)` | Реализация этого trait и явная ветка выбора; новый общий интерфейс не нужен |
| `parakeet_engine/model.rs`, `lib.rs`, `build/onnxruntime.rs` | ONNX Runtime и поставка Windows DLL | Использовать уже выбранный CPU EP; Parakeet nemo128/TDT не совместимы с log-mel64/CTC/RNNT GigaAM |
| `audio/decoder.rs`, `audio_processing.rs`, `vad.rs` | Декодирование, mono f32 16 kHz, ресемплинг, VAD | Передать штатные сегменты готовому GigaAM-движку |
| `audio/transcription/worker.rs`, `recording_commands.rs`, `recording_manager.rs` | Очередь, последовательный worker, flush/ожидание при остановке, сохранение | Передать адаптер с зафиксированным выбором и удержать до конца существующего завершения; не создавать новую очередь |
| `audio/import.rs`, `retranscription.rs` | Прогресс, отмена, циклы обработки, ошибки, сохранение | Ветка `gigaam` до бинарного выбора Parakeet/Whisper и соответствующий cleanup |
| `audio/common.rs` | Временные метки, transcripts.json, splitter, lifecycle lock для существующих движков | Сохранить общий процесс; готовый внутренний splitter GigaAM обеспечивает строгий предел поверх общего разбиения ±3 секунды |
| `retranscription.rs` | Распознавание до сохранения; DELETE/INSERT в транзакции | Не подавлять ошибку адаптера и не входить в замену текста с техническим пустым результатом |
| `api/api.rs`, `database/repositories/setting.rs`, `ConfigContext.tsx` | Хранение и восстановление provider/model | Подключить значение `gigaam`; новая таблица настроек не требуется |
| `TranscriptSettings.tsx`, `useTranscriptionModels.ts`, `transcription-model-readiness.ts` | Настройки, общий список файловых диалогов, проверка готовности | Дополнить существующие типы/списки и readiness данными GigaAM; не создавать параллельные диалоги |
| `gigaam_engine/…`, `GigaAMModelManager.tsx`, `lib/gigaam.ts` | Уже добавленные каталог, загрузчик, препроцессинг, CTC/RNNT, раздел загрузок | Переиспользовать; добавить выбор готовой модели и небольшой provider |

`api_save_transcript_config` не блокирует изменение модели при записи. `RecordingSettings` ограничивает аудиоустройства, а не этот выбор. Arc существующего ParakeetEngine сам по себе не фиксирует модель: внутри есть изменяемый current_model. Поэтому гарантия выбора операции требует небольшого GigaAM-дополнения, а не копирования этой особенности.

Дополнительная проверка перед обновлением задач: recording_commands.rs ждёт transcription task через timeout 600 секунд, после чего продолжает shutdown; далее provider для unload перечитывается из настройки. Это ограничение существующего завершения, а не доказательство полного drain. Story 1.9 должна явно обработать GigaAM-владение/ошибку на этом пути. Глобальную переделку stop/очередей и увеличение таймаутов как проверку производительности не добавлять.

## Покрытие требований по исходникам

«Частично» означает готовый компонент или общий механизм без завершённого пользовательского маршрута. Отсутствие интеграции GigaAM не означает отсутствие самого процесса в Meetily.

| ID | Фактическое состояние | Что остаётся |
| --- | --- | --- |
| FR1 | Каталог содержит четыре FP32 ID; интерфейс показывает раздел загрузок | Выбор для распознавания в настройках и обоих файловых диалогах |
| FR2 | Команды загрузки, прогресс, ошибки и общий механизм настройки уже есть | Связать выбор GigaAM с существующим сохранением/восстановлением |
| FR3 | Проверки состава/размеров/SHA-256, staging, отмена, повтор, rollback готовы | Native UI-проверка целого пути; не переписывать загрузчик |
| FR4 | Запись/очередь/flush/сохранение существуют | Передать GigaAM в этот процесс |
| FR5 | Импорт существует; выбор `use_parakeet`, иначе Whisper | Добавить GigaAM-ветку в существующую операцию |
| FR6 | Повторная транскрибация и транзакционное сохранение существуют | Добавить GigaAM-ветку |
| FR7 | Rust CTC/RNNT работают с локальными файлами и CPU, без Python-сервиса | Подтвердить offline пользовательских сценариев |
| FR8 | Параметры файловых операций передаются аргументами; live язык перечитывается | Зафиксировать tuple до decode/queue, удерживать неизменный адаптер до конца операции |
| FR9 | Движки проверяют model ID, пакет, ABI/тензоры и возвращают ошибки | Проверка русского/авто, маршрутизация/readiness/cleanup без fallback на Whisper |
| FR10 | E2E и confidence=None реализованы в движках; timestamps уже существуют | Убрать числовую подстановку confidence только для GigaAM в общих wrappers |
| FR11 | Отмена/ошибки/транзакция есть; файлы защищаются лишь незавершёнными правками 1.5 | Владение адаптером и защита пакета до завершения последнего native worker; проверить реальные пути отмены/сохранения |
| FR12 | Команды/раздел загрузок gated Windows x64; существующие движки сохранены | Gating выбора/readiness и smoke затронутых путей Whisper/Parakeet |
| NFR1 | CPUExecutionProvider явно выбран в CTC/RNNT; backend gating есть | Проверка полной Windows-интеграции |
| NFR2 | Производительность принята достаточной | Исключение бенчмарков сохраняется |
| NFR3 | Manifest, закреплённые revisions, лицензии, проверка пакета готовы | Переиспользовать существующий контракт |
| NFR4 | Проверки синтетические; GigaAM-движки не логируют текст | В worker/import/retranscription есть text-bearing логи; исключить их для GigaAM |
| NFR5 | Компонентные Windows-проверки есть | Матрица 4 модели × 3 сценария в native приложении не выполнена |
| NFR6 | Текущая ветка сохранена; аудит не менял приложение | Продолжать без commit/push/замены установки без запроса |
| UX-DR1 | Раздел загрузок добавлен, базовые интерфейсы продукта существуют | Подключить выбор в этих интерфейсах |
| UX-DR2 | Статусы/ошибки загрузчика готовы | Не предлагать неготовые модели к запуску, показать ошибки readiness |
| UX-DR3 | Раздел загрузок скрывается на неподдерживаемой платформе | Сохранить default и распространить gating на выбор |

AD-1/2/6 требуют интеграции существующих точек; AD-3 выполнен для публикации пакета, но защита активного использования не завершена; AD-4 не завершён; вычислительная часть AD-5 реализована, timestamps и сохранение переиспользуются.

## Текущая незавершённость

`gigaam_engine/mod.rs` объявляет `pub mod session;`, однако ни `session.rs`, ни `session/mod.rs` нет. В downloads.rs добавлены per-model gates/lease, в commands.rs расширена видимость manager; потребителя ещё нет. Это статический блокер компиляции, не результат запуска cargo. При следующей реализации сначала привести частичные правки к обновлённой Story 1.5 и восстановить компиляцию. В рамках документирования исходники не исправлять и не откатывать.

## Вывод для планирования

Сохраняются один эпик и ID историй 1.1–1.10. Готовые 1.1–1.4 не выполняются заново. 1.5 ограничивается адаптером, фиксацией выбора и минимальной защитой пакета; 1.6–1.9 подключают его к существующему продукту. 1.10 проверяет итоговую функцию. Это коррекция способа реализации без сокращения согласованных гарантий и без вывода о проценте готовности всей функции.

## Дополнение CC-2: повторный аудит 1.1–1.4

[Покомпонентный пересмотр](reuse-audit-1-1-to-1-4.md) заменяет прежнее безусловное сохранение уже реализованных компонентов. Перед адаптером в 1.5 revision 3 консолидировать две общие функции: streaming-to-writer из существующего Parakeet и одинаковую очистку текста Parakeet/GigaAM. Package validation/publication и log-mel/CTC/RNNT GigaAM сохраняются по конкретным ABI/state-различиям, не по факту ранее выполненной работы. Parakeet содержит обычную RNNT-ветку; прямое использование её через текущий combined decoder_joint не соответствует выбранному GigaAM ABI/cache. Допускается ограниченное изменение Parakeet для двух общих функций с регрессионной проверкой; новый общий lifecycle/decoder framework не требуется. Все AD и пользовательские гарантии сохранены; после изменения cleanup нужны адресные model smoke, а прежние результаты не объявляются проверкой нового кода.
