# GigaAM: локальное распознавание на CPU в Windows

## Why

Добавить пользователям Windows-версии Meetily выбор моделей GigaAM для локального распознавания русской речи. CPU-исполнение упрощает поставку и исключает зависимость этой функции от GPU-бэкенда.

## Capabilities

- **CAP-1**
  - **intent:** Пользователь может выбрать, скачать и использовать любую из четырёх моделей GigaAM наряду с существующими моделями приложения.
  - **success:** В существующем интерфейсе доступны `v3_ctc`, `v3_rnnt`, `v3_e2e_ctc`, `v3_e2e_rnnt` в FP32; файлы скачиваются из приложения, выбранная модель сохраняется и используется при распознавании.
- **CAP-2**
  - **intent:** Пользователь может применять выбранную модель GigaAM во время записи, при импорте аудио и при повторной транскрибации.
  - **success:** Для каждой из четырёх моделей каждый из трёх сценариев создаёт и сохраняет осмысленный текст синтетической русской речи локально на CPU, без интернета после скачивания. Начатая операция завершается на исходной модели; новый выбор применяется к следующей операции.

## Constraints

- Целевая платформа новой функции — Windows x64; GigaAM использует только CPU и обычные FP32-файлы.
- Движок встроен в приложение; отдельная программа, сервер или установленный пользователем Python не требуются.
- Работать в текущей ветке `fix/whisper-library-upgrade`, сохраняя существующие изменения. Не коммитить, не публиковать и не менять установленное приложение без отдельного запроса.
- Использовать текущую Tauri-архитектуру; не подключать архивный `backend/`.
- Максимально переиспользовать существующие классы, методы и процессы Meetily: `TranscriptionProvider`, настройки provider/model, подготовку аудио, запись, очереди, отмену, временные метки и сохранение. Добавлять только отсутствующий GigaAM-адаптер и необходимые ветки интеграции; перед новым механизмом показать конкретный пробел существующего кода.
- Сохранить существующее поведение Whisper и Parakeet, включая их способы ускорения.
- Для проверки использовать синтетические данные; реальные встречи и персональные настройки не включать в Git.
- Обязательный сопроводительный документ — `ARCHITECTURE-SPINE.md`; его AD-1–AD-6 определяют архитектурные правила для CAP-1 и CAP-2. До реализации потребителей пакетов выполнить указанную в нём техническую подготовку общего контракта артефактов.

## Non-goals

- GPU-ускорение GigaAM, включая DirectML, Vulkan и CUDA; варианты INT8.
- Бенчмарки, измерения производительности и пороги скорости как условия приёмки.
- Другие поколения GigaAM, Multilingual, обучение моделей и новые функции диаризации.
- Общая переработка жизненного цикла существующих Whisper/Parakeet.
- Отдельная инфраструктура операций GigaAM: универсальная фабрика сессий, новые очереди/планировщики, собственные процессы импорта, записи или сохранения встреч.

## Success signal

В Windows-приложении доступны четыре FP32-модели GigaAM; каждая успешно выполняет все три сценария локально на CPU. Функционально проверены сохранение результата, фиксация модели на время операции и переключение обратно на Whisper/Parakeet.

## Assumptions

- По явному решению пользователя производительность CPU считается достаточной; это принятое допущение, а не измеренный результат.
- Компонентная готовность подтверждается отдельно от готовности пользовательских сценариев; наличие модели или успешный тест движка не означает завершения CAP-1/CAP-2.

## Implementation baseline — 2026-10-30

- Контракт четырёх пакетов закреплён в `model-contract.md` и общем manifest; имеются отчёты Windows CPU-проверок всех четырёх моделей и Rust CTC/RNNT. Загрузчик, каталог, log-mel и ограничение длины уже реализованы; их используем дальше.
- Выбор GigaAM для распознавания и подключение к записи, импорту и повторной транскрибации ещё не реализованы. Остановленная история 1.5 содержит незавершённые правки; текущая рабочая копия не является проверенной сборкой.
- Текущее покрытие требований, точки переиспользования и ограничения: [brownfield-audit.md](brownfield-audit.md). Последовательность оставшейся работы: [epics.md](../../planning-artifacts/epics.md). Это снимок анализа исходников и существующих evidence, не новая native приёмка.

## Дополнение CC-2: повторный аудит 1.1–1.4

[Покомпонентный пересмотр](reuse-audit-1-1-to-1-4.md) заменяет прежнее безусловное сохранение уже реализованных компонентов. Перед адаптером в 1.5 revision 3 консолидировать две общие функции: streaming-to-writer из существующего Parakeet и одинаковую очистку текста Parakeet/GigaAM. Package validation/publication и log-mel/CTC/RNNT GigaAM сохраняются по конкретным ABI/state-различиям, не по факту ранее выполненной работы. Parakeet содержит обычную RNNT-ветку; прямое использование её через текущий combined decoder_joint не соответствует выбранному GigaAM ABI/cache. Допускается ограниченное изменение Parakeet для двух общих функций с регрессионной проверкой; новый общий lifecycle/decoder framework не требуется. Все AD и пользовательские гарантии сохранены; после изменения cleanup нужны адресные model smoke, а прежние результаты не объявляются проверкой нового кода.
