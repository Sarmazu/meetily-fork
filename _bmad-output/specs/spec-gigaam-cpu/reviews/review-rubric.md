## Findings

1. **High — ABI и snapshot откладываются слишком поздно для независимо строящихся декодеров и загрузчика.** Deferred требует закрепить snapshot и ABI «перед реализацией загрузчика», тогда как декодер/preprocessor может быть реализован раньше по другому снимку. Оба будут буквально соответствовать текущему документу. Закрепить единый manifest/ABI/preprocessing/detokenization baseline до реализации любого потребителя пакета и до параллельного исполнения соответствующих задач. Точные значения разрешено установить отдельной первой задачей, но её завершение должно быть обязательной зависимостью всех потребителей. Это не требует сейчас скачивать модели или менять выбранный FP32-набор.

2. **Medium — граница Windows-специфичного UI не сформулирована.** SPEC ограничивает новую функцию Windows x64, но AD-2 требует модели в существующих списках без указания платформенной доступности. UI на macOS/Linux может рекламировать неподдерживаемую функцию, если нативная часть условно собрана только для Windows. Явно связать видимость/доступность управления GigaAM с поддержкой native-бэкенда на Windows x64; существующие платформы Whisper/Parakeet не изменять. Не обязательно предписывать конкретный способ capability detection.

## Checklist

- CAP-1/CAP-2 покрыты: четыре model ID, FP32, CPU, встроенный выбор/скачивание, запись/импорт/повторная транскрибация.
- Без performance checks: явно соблюдено, функциональные тесты не выданы за benchmark.
- Текущая ветка/сохранение локальных изменений: унаследовано из SPEC.md, противоречий нет.
- AD-1..AD-6 имеют Binds/Prevents/Rule; state ownership и граница operation/session обозначены.
- Настройки и запущенная операция разделены; ошибка не вызывает скрытую замену движка; readiness требует полного пакета.
- Brownfield согласован: существующий TranscriptionProvider допускает новый адаптер; import/retranscription сегодня выбирают между двумя движками, поэтому явная новая ветка действительно нужна.
- Операционный envelope покрыт Windows-поставкой, app_data_dir, offline inference, staging/проверкой пакетов, штатными ошибками и приватностью логов.
- Точные версии текущих Rust/ORT указаны как сохранение существующего baseline, а не заявление о latest. Web-проверку технологий оценивает отдельная обязательная review lens.
- Дополнительного документа для неразработчика не требуется: согласован компактный документ и облегчённое обсуждение.
