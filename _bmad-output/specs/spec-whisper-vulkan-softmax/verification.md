# Приёмка и регрессионная проверка

Исторические сборки с минимальным patch подтверждают причину. Выбрано обновление официальной библиотеки до whisper-rs 0.16.0 / sys 0.15.0; новая сборка частично проверена; полная матрица остаётся обязательной для общей тестовой сборки.

## Перенос приёмки — решение 2026-10-30

Оставшийся live-тест переносится на общую тестовую сборку после будущих фич. Это перенос срока, а не исключение критерия или разрешение переходить к завершению Build. [Сводка результатов и открытых пунктов](../../implementation-artifacts/whisper-acceptance-handoff.md) сохранена отдельно. Проверки ниже не повторять сейчас; короткие проверки будущих изменений не отменяются. Отчёты привязаны к уже проверенным сборкам и не подтверждают автоматически новый общий кандидат.

## Синтетический образец

`evidence/synthetic-en.wav`: PCM16 mono, 16000 Hz, 202080 frames, 12.63 s. Исходная речь:

> This is a synthetic speech recognition test. We are checking the local transcription engine. The quick brown fox jumps over the lazy dog.

Для каждого содержательного результата нормализовать регистр, пунктуацию и пробелы. Проверять английский текст с фразами `synthetic speech recognition test`, `local transcription engine`, `quick brown`. Обычная локальная ошибка fox/facts допускается; пустой результат и посторонние русские фразы не принимаются. Значение confidence из текущего приложения зависит от длины текста и не заменяет проверку содержания.

## Матрица CAP-1

| Проверка | Критерий |
|---|---|
| Native GPU softmax | При KY=0 и KY>0 вычисления конечны, суммы вероятностей и численные результаты соответствуют CPU reference в допуске, выбранном и обоснованном техническим планом. Проверка выполняет операцию; поиск строки исправления не является тестом. На affected GPU дефектный вариант демонстрирует расхождение, исправленный проходит. |
| Import | В исправленном Tauri-приложении на Windows/Radeon 780M large-v3-turbo распознаёт exact WAV по содержанию. Логи подтверждают Vulkan и отсутствие диагностического отключения FP16. |
| Retranscription | Повторная транскрибация синтетической встречи проходит тот же критерий содержания. Реальные встречи не использовать. |
| Live | Запись синтетического playback средствами нативного приложения даёт ожидаемые английские фразы; проверить окончательный сохранённый результат после stop, не только промежуточное появление текста. |
| Provider switching | В рамках синтетической проверки Parakeet→Local Whisper→Parakeet не требует перезапуска как обхода; каждый провайдер даёт текст ожидаемого содержания. Другие выявленные причины зависания оформляются отдельно. |
| CPU / Parakeet smoke | На известном образце сохранено baseline рабочее поведение CPU и Parakeet; модели, встречи и настройки не мигрируют/не удаляются. |
| Build compatibility | Целевая Windows-сборка и необходимые проверки компиляции затронутых платформ соответствуют docs/BUILDING.md. Проверены новая API сегментов/таймингов/ошибок, locked graph whisper-rs 0.16.0 / sys 0.15.0, backend features и Windows portability flags. Нет локального vendor/path override для Whisper; точные команды и доступность платформ уточняет Build до реализации. |

В CI без GPU native GPU-проверку явно отмечать skipped/не выполненной; CPU или браузерный dev-server не дают права объявить native сценарии пройденными. Технический план выбирает минимальное подключение численного regression test к runner проекта и численные допуски до реализации. Целевая версия уже выбрана пользователем; автоматически менять её или возвращаться к backport нельзя.

## Доказательства при завершении

Зафиксировать commit/версию исправленной сборки, выбранный способ доставки upstream fix, фактически запущенные команды, native результаты трёх сценариев и замеченные ограничения. Успех означает устранение воспроизводимого дефекта, не гарантию идеального ASR для любой записи.

## Последовательность BMAD

1. Постановка, выбор обновления и технический план согласованы; реализация и частичная проверка выполнены в отдельной task branch.
2. Решение 2026-10-30: сохранить результаты и отложить оставшуюся live-приёмку до общего кандидата после будущих фич. Текущий Build остаётся in-progress; новая спецификация сейчас не создаётся.
3. Будущие фичи оформляются отдельно. Их короткие проверки сохраняются; повторная тяжёлая Windows-сборка нужна при готовности общего кандидата либо новой технической причине.
4. На общем кандидате выполнить обязательную матрицу, разобраться с открытой семантикой Parakeet и обновить evidence. Не считать прежние PASS автоматическим доказательством нового кандидата.
5. Затем продолжить встроенное review Build и bmad-walkthrough для пользовательской приёмки. bmad-code-review — дополнительная необязательная проверка сверх встроенной.
6. Коммит/push/PR и установка исправленной сборки — отдельные явно запрошенные действия.
