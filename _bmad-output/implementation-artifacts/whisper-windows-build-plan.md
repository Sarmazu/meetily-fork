# Подготовка Windows и тестовая сборка Whisper

Дата: 2026-10-29. Продолжение step 3 BMAD Build, ветка `fix/whisper-library-upgrade`.
Пользователь поручил подготовить Windows-среду и выполнить компиляцию через субагента с чистым контекстом.

## Порядок исполнения

1. Прочитать утверждённую спецификацию `spec-whisper-library-upgrade.md`, её context-файлы, отчёт `whisper-upgrade-verification.md`, `docs/BUILDING.md` и Windows-часть `.github/workflows/build.yml`. Проверить WSL interop, Windows-версию, свободное место, установленный MSVC/SDK, Rust, Node, pnpm, CMake, Python, LLVM/libclang и Vulkan SDK. Не выводить секреты и персональную конфигурацию.
2. Переиспользовать подходящие инструменты. Недостающие компоненты получать из официальных источников: VS 2022 Build Tools с C++ x64 и Windows SDK, Rust MSVC >=1.88 (предпочтительно 1.88.0), Node 20, pnpm 9.15.9, CMake >=3.21, LLVM/libclang, Vulkan SDK с glslc. Сначала проверить требования и параметры установщиков по официальной документации. Предпочесть изолированные portable/user-local инструменты; системный MSVC installer допустим в рамках поручения подготовки среды. Не удалять/обновлять существующие toolchains принудительно, не менять глобальный PATH, не перезагружать Windows автоматически. Если требуется UAC/интерактивное подтверждение, вернуть точную инструкцию пользователю и продолжать независимые шаги. Проверять версии после каждой установки.
3. Создать отдельную рабочую копию исходников на Windows NTFS для сборки, включая текущие незакоммиченные task-изменения. Использовать отдельный task-каталог без перезаписи чужих файлов. Не копировать .git, node_modules, target, записи, пользовательские конфиги или секреты. Не коммитить и не отправлять исходники во внешние сервисы. Сверить хеши task-файлов с исходной WSL-копией. Сохранить исходные manifests и lockfile; не выполнять dependency update.
4. Запускать Windows tools через PowerShell с MSVC environment, отдельными Cargo/Rustup homes и новым CARGO_TARGET_DIR. Сохранить Windows portability hook `CMAKE_PROJECT_INCLUDE` и `RUSTFLAGS=-C target-cpu=x86-64-v2` из workflow. Установить frontend зависимости с frozen lockfile, собрать CPU llama-helper и необходимые runtime assets согласно build.rs/workflow, затем тестовое Tauri release-приложение с `--features vulkan --no-bundle` (без installer, signing, publish и production credentials). При необходимости использовать отдельный Tauri config для task output/runtime путей; не менять идентичность или рабочую установку приложения.
5. Выполнить locked graph, Windows cargo check/test для whisper_engine и Vulkan numerical runner в новом build directory. Проверить фактические native compiler flags AVX2/no AVX512 и ordinary FP16; skip GPU не считать pass. Сохранить stdout/stderr и коды возврата локально, в репозиторий записать только очищенный отчёт. Не запускать app против реальных встреч и не заменять установленный exe.
6. Отчёт `whisper-windows-build-verification.md`: версии и места инструментов, команды, результаты, compiler flags, путь exe и его SHA256, runtime dependencies, возможность отдельного запуска, blockers и инструкция воспроизведения. Если блокер, указать последний успешный шаг и требуемое действие, без маскировки fallback.

## Критерий результата

Получен Windows x64 release exe с Vulkan из текущих исходников и подтверждено его окружение; численный regression фактически выполнен либо явно отмечен незапущенным. CAP-1 import/retranscription/live и CPU/Parakeet smokes остаются отдельной нативной приёмкой. Build не объявлять завершённым до прохождения матрицы утверждённой спецификации. Публичные API/форматы данных не меняются.
