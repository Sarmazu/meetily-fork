# BMAD для Meetily и Codex

Установлен официальный стабильный BMAD Method **6.12.4**: модули `core` и
`bmm`, только интеграция Codex, без устаревших compatibility shims.
Это релизная v6, а не preview v7. Переход на другую версию выполняется отдельной
задачей с проверкой изменений.

Источник: [релиз v6.12.4](https://github.com/bmad-code-org/BMAD-METHOD/releases/tag/v6.12.4),
commit `bab9082c3e884e0d72c759bcd1a6d90bcc01be84`.
Проверено 2026-10-23; npm-пакет установщика — `bmad-method@6.12.4`.

## Использование

Откройте новую сессию Codex из корня репозитория. Codex обнаруживает корневой
`AGENTS.md` и навыки в `.agents/skills/`. Отдельный `/init` не требуется.
Если текущая сессия ещё не видит новые навыки, начните новую сессию.

- Для выбора следующего шага вызовите `$bmad-help` и опишите задачу.
- Для подготовки или обновления контекста используйте `$bmad-project-context`.
- Для требований, архитектуры и декомпозиции доступны `$bmad-prd`,
  `$bmad-architecture` и `$bmad-create-epics-and-stories`.
- Для согласованной доработки используйте `$bmad-build`, для отдельного ревью —
  `$bmad-code-review`.

Для существующего Meetily сначала сформулируйте конкретное изменение и критерии
приёмки. Не создавайте вымышленный PRD или backlog всего продукта.
Запуск навыка реализации может менять код; для ознакомления явно просите только
анализ и план без реализации.

## Файлы и настройки

- `.agents/skills/` — 29 установленных навыков и их ресурсы; хранить в Git.
- `_bmad/` — runtime, манифесты и настройки; хранить в Git, кроме локальных файлов.
- `_bmad/custom/config.toml` — командные overrides, включая русский язык.
- `_bmad/config.user.toml` и `_bmad/custom/config.user.toml` — персональные
  настройки, исключённые из Git.
- `_bmad/render/` — генерируемые инструкции; содержимое исключается штатным
  `.gitignore` BMAD, пересоздаётся при запуске навыка.
- `_bmad-output/planning-artifacts/` и `_bmad-output/implementation-artifacts/` —
  штатные места для результатов работы. Проверяйте содержимое перед добавлением
  в Git; используйте синтетические данные вместо реальных встреч.

`_bmad/config.toml` управляется установщиком. Вносите постоянные командные
настройки в `_bmad/custom/config.toml`, а персональные — в `config.user.toml`.
`CLAUDE.md` сохранён; интеграция Claude Code не установлена. При работе через
Codex используйте `AGENTS.md`, а не устаревшие сведения о текущей ветке в
других документах. Порядок отправки изменений в upstream проверяется отдельно.

## Runtime и повторяемая установка

Установщик требует Node.js **20.12+**; runtime навыков — `uv` и Python **3.11+**
(scripts этого релиза используют `tomllib`). `uv` может предоставлять Python
самостоятельно. Здесь установщик запускался через уже имеющийся Node.js 20.20.0;
системный Node.js не менялся. `uv 0.13.5` установлен в `~/.local/bin/uv` без
изменения shell-профиля.

Из корня проекта, с подходящим Node.js и `uv` на `PATH`:

```bash
npx --yes bmad-method@6.12.4 install \
  --directory "$PWD" \
  --modules bmm --tools codex \
  --communication-language Russian \
  --document-output-language Russian \
  --output-folder _bmad-output --no-shims --yes
```

Для уже существующей установки добавьте `--action update`. Сначала сохраните
свои изменения и просмотрите diff после запуска: установщик обновляет файлы.
Не используйте неприкреплённые `latest`, `next` или исходники `main` при
воспроизведении этой установки. Установка BMAD не требует установки зависимостей
или сборки приложения Meetily.

## Проверка

```bash
uv run _bmad/scripts/resolve_config.py --project-root "$PWD"
uv run _bmad/scripts/resolve_customization.py \
  --project-root "$PWD" --skill .agents/skills/bmad-project-context --key workflow
```

Первый вызов выводит объединённую конфигурацию, в том числе локальные настройки;
не публикуйте его вывод без проверки. Версии и список модулей находятся в
`_bmad/_config/manifest.yaml`, каталог навыков — в
`_bmad/_config/skill-manifest.csv`.

В sandbox с недоступным домашним кэшем можно задать
`UV_CACHE_DIR=/tmp/meetily-bmad-uv-cache`. Это настройка окружения, а не изменение
runtime BMAD. Проверка UI в браузере не подтверждает работу нативной записи.

Проверка внедрения 2026-10-23: resolver конфигурации и customization выполнены,
`bmad-build` успешно сгенерировал инструкции без запуска реализации. В новой
одноразовой read-only сессии Codex обнаружены `AGENTS.md` и навыки BMAD;
`bmad-help` подготовил гипотетический план без изменения приложения.
Проверены 29 точек входа навыков и SHA-256 230 ресурсов по штатному манифесту.
Пять записей манифеста относятся к отсутствующим Python bytecode-кэшам
`__pycache__`; это не исполняемые исходники и не обязательные runtime-ресурсы.
Сборка и нативная запись Meetily в рамках этой установки не проверялись.

## Обновление и удаление

Обновляйте BMAD в отдельной ветке, выбирая конкретный официальный релиз.
Повторите проверку контекста, конфигурации, доступности навыков в новой сессии
Codex и изменений runtime. Не заменяйте командные overrides правками в
сгенерированных файлах.

Для удаления сначала сохраните нужные артефакты и personal overrides. Удаляйте
только перечисленные в манифесте навыки BMAD, его `_bmad/` и управляемый блок
в `AGENTS.md`; сохраняйте любые сторонние навыки и инструкции. Отдельно решите,
какие документы из `_bmad-output/` оставить. `uv` — пользовательский инструмент,
он может использоваться другими проектами и не удаляется вместе с интеграцией.
